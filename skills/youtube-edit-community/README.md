# YouTube横動画の編集パッケージ（v6）

版番号は同梱の `VERSION` ファイルにあります。問い合わせのときはこの番号を添えてください。

ぼくが横動画を編集するときの、白い字幕・見出し・丸ワイプ・画像Bロールを試すためのパッケージです。エージェントへ素材と希望を渡し、30〜45秒の音付き試作を確認してから本編へ進めます。完成MP4を約束するものではありません。

**Mac専用です。Apple Silicon搭載のMacが必要で、Intel MacとWindowsは対象外です。**

**Claude Code と Codex の両方で使えます。** どちらも Agent Skills 形式（`SKILL.md` ＋ `scripts/` ＋ `references/`）を同じように読むため、置き場所と権限設定だけが違います。編集処理そのものは同梱の Python と Remotion が行うので、動作と仕上がりはどちらでも同じです。

## 最初の準備

導入するソフトはFFmpeg 8.x、Python 3.9以上と音声認識・画像処理用のモジュール、Node.js 20以上、Remotionです。初回は、必要なソフトと音声認識モデルの取得にネット接続が必要です。準備後の動画処理はローカルで行います。フォントは同梱しています。

### Claude Code で使う場合

1. `youtube-edit-community` フォルダを `~/.claude/skills/` の中へ置きます。Finderで「移動」→「フォルダへ移動」を選ぶと、この場所を入力できます。フォルダがなければ作成します。
2. Claude Code を起動し、[導入の依頼文](#導入の依頼文)を貼り付けます。

### Codex で使う場合

1. `youtube-edit-community` フォルダを `~/.agents/skills/` の中へ置きます。フォルダがなければ作成します。
2. `~/.codex/config.toml` に次を追記します。ファイルがなければ作成します。`OUTPUT` は完成動画を書き出すフォルダに置き換えます。

```toml
[[skills.config]]
path = "~/.agents/skills/youtube-edit-community"
enabled = true

[sandbox_workspace_write]
network_access = true
writable_roots = [
  "~/.agents/skills/youtube-edit-community",
  "~/.cache/huggingface",
  "~/Documents/Videos",
]
```

- `[[skills.config]]` は、スキルの置き場所を明示して有効にする指定です。`~/.agents/skills/` を自動で読む版でも、書いておけば確実です。
- `network_access` は、初回のソフト導入と音声認識モデルの取得に必要です。
- `writable_roots` は、書き込みを許可するフォルダです。パッケージ内（Remotionの導入先）、音声認識モデルの保存先、動画の出力先の3つが必要です。出力先を変えるたびに、この行を足してください。
- Codex は既定で、作業フォルダの外への書き込みとネット接続を止めます。上の3つ以外を許可する必要はありません。

3. Codex を再起動します。スキルは起動時に読み込まれます。
4. [導入の依頼文](#導入の依頼文)を貼り付けます。

素材の読み込みだけが止まる場合は、素材フォルダを `writable_roots` に足すのではなく、素材を出力先の隣へコピーしてください。読み取りは既定で通ります。

### 導入の依頼文

```text
youtube-edit-communityを使いたいです。
SKILL.mdとreferences/workflow.mdを読み、最初にscripts/check_env.shを実行してください。
不足するものを確認して導入し、remotionフォルダでnpm ciとnpm run setupを実行してください。
```

導入コマンドは環境チェックに表示されます。READYになるまでのエラーは、そのままエージェントへ渡してください。

### スキルとして読み込まれないとき

パッケージ直下の `AGENTS.md` を使います。`youtube-edit-community` フォルダを作業フォルダの中に置いて、次の文を渡してください。スキルの自動認識を使わずに、同じ手順で動きます。

```text
youtube-edit-community/AGENTS.md を読んで、その手順に従ってください。
```

## 素材と希望を渡す

人物動画、画面収録、別録り音声のうち、手元にあるものを渡します。主音声は素材ごとに測定し、別録り音声を原則優先して1本選びます。差が小さい場合は選択をお聞きします。使いたい音声・使わない音声の指定があれば、その指定を優先します。元素材とは別の出力フォルダも指定します。

写真やスクリーンショット（PNG・JPEG・HEIC）も一緒に渡せます。縦長のスクショは人物の隣に、縦の写真はガラス背景の上に、横長のWeb画面は全画面で見せます。人物の目線に合わせて配置し、試作で確認します。

| プラン | 向いている内容 |
|---|---|
| A シンプルトーク | 人物と声を中心に見せたい動画。画面は必要なところへ挿入します |
| B 見出し付き解説 | 話題を見出しで伝えたい動画。画面に合わせて丸ワイプを出し入れします |
| C 画面実演＋丸ワイプ | 操作画面を中心に見せたい動画。画面表示中は丸ワイプを出します |

最初の依頼文は [examples/request.md](examples/request.md) にあります。比較の見た目は [mock/index.html](mock/index.html) をブラウザで開いて確認できます。モックだけでは音声同期を確認できません。

## 試作を確認する

声と口元が合っているか、字幕が正しいか、画面の文字が読めるか、丸ワイプが操作の邪魔になっていないかを確認します。位置は左右、大きさは標準・小さめ、字幕色を変更できます。見出しの左右・帯と文字の色も設定できます。人物素材がない画面解説でも、見出しを画面の上に表示します。

修正したい箇所は、試作の時刻と希望を伝えてください。採用する場合は「この設定でフルを作って」と伝えます。本編は10〜15分を目安にしますが、素材の内容に応じて尺は変わります。

## 出力と次回の使い方

指定した出力フォルダの `work` に、`final.mp4`、字幕ファイルの `final.srt`、検品結果の `qc.json` ができます。出力フォルダ直下の `settings.json` は、採用した見た目や音声の設定です。

次回は、この `settings.json` と新しい素材を渡して「前回と同じ設定で」と伝えてください。

同じ出力フォルダで再実行すると、前の試作や中間ファイルが更新されます。試作と本編を両方残す場合は、出力フォルダを分けてください。

技術検品のPASSだけで、字幕全文の校正や全編視聴まで完了したとは扱いません。未実施の確認は、結果と分けて記録します。公開や投稿は自動で行いません。

フォントの利用条件は [fonts/OFL.txt](fonts/OFL.txt)、操作の詳細は [references/workflow.md](references/workflow.md) にあります。
