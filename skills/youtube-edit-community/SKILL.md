# YouTube横動画編集：3つの基本プラン

実行順は **scripts/check_env.sh → probe → transcribe → sync → 全文を読んでkeep_segments.jsonを作る → cut → captionsで初稿 → caption-rules.mdに従い全文を1枚ずつ書き直す → --captionsで渡す → scenes.jsonを作る → render → finalize → qc** に固定する。編集の実行には同梱の `scripts/ytedit.py` を使う。

最初に[制作仕様と検品](references/workflow.md)を読む。環境がない場合、完成MP4を作れると約束せず、不足する機能を具体的に示す。環境チェックで示された必要な導入を行い、READYを確認する。初回の依存・ブラウザ・Whisperモデル取得にはネット接続が必要。

## 最初の選択は3つ

| プラン | 主役 | 初期設定 |
|---|---|---|
| A シンプルトーク | 人物と声 | 白いフルテロップ。画面収録は必要な場面にワイプなしで挿入。常設見出しなし |
| B 見出し付き解説 | 話題と説明 | 白字幕＋左上の見出し。必要な画面を挿入し、操作中は丸ワイプ、細部を読む間はワイプなし |
| C 画面実演＋丸ワイプ | 操作画面 | 大画面＋右下の標準丸ワイプ。下に白字幕。導入・感想・まとめでは人物を大きく戻す |

話中心ならB、操作中心ならC、人物と声中心ならAを提案する。今回の明示指定と採用済みの設定を優先し、すべての選択肢を聞き直さない。初期値は `presets/A.json`・`B.json`・`C.json`。

## 素材から試作へ

1. 素材、内容、目標尺、出力先、採用済み設定を受け取る。足りない必須情報だけまとめて尋ねる。元ファイルを変更せず、出力先を分ける。
2. `probe` で解像度・fps・実尺と全音声ストリームを確認する。主音声の既定は `auto`。有音率・音量・ノイズ床・8kHz以上の比率を測り、`probe.json` の `master_choice.reason` を1行で報告する。動画1本ならその音声、別録りがある場合は原則それを採用する。`master_choice.ambiguous=true`（ノイズ床差<3dBかつ高域比の相対差<20%）なら工程を止めて利用者に候補を聞き、回答を `probe --master mic|camera|screen` に渡す。利用者の「使わない」は `--exclude-master`（複数回指定可）に渡す。明示指定を測定より優先し、主音声は1本だけ使う。他の音声は同期専用。4ch以上・デコード不可の音声は選ばず、有音の最初の1〜2chストリーム番号を後工程でも使う。
3. `transcribe` の単語時刻は主音声基準。辞書は同梱 `references/vocabulary.json` と、任意の `<out>/vocabulary.local.json`（`initial_prompt_terms` と `corrections`）を使う。`transcript.gaps.json` の有音ギャップ・再取得語数、`transcript.validation.json` の0秒単語結合数・本文一致を確認する。全文を読んで、無音・操作待ち・言い直し・重複を判断する。`sync` の相関とドリフトを確認し、警告があれば原音を照合してからカットへ進む。
4. 保持区間を作り、`cut` の `timeline.json` に従って字幕と表示状態を完成時刻へ揃える。`captions` は初稿生成。[字幕ルール](references/caption-rules.md)と[承認済み手本](references/caption-sample.json)を読み、全文を1枚ずつ書き直す。1行・句読点なし・平均13字前後・最大23字。言い換えや要約をせず、フィラー・言い直しを除き、意味の切れ目で分ける。5分程度ごとに途中結果を保存する。
5. `scenes.json` は一定間隔で機械的に切り替えず、発話に一致する表示にする。Aは画面表示時も `face:false`。Bは操作中 `true`、細部を読む間 `false`。話題転換で見出しを更新する。Cは画面表示中 `true`、導入・感想・まとめは `presenter` に戻して `false`。
6. 30〜45秒の音付き試作を同じ合成経路で作る。`preview --range s e` の範囲は主音声時刻。`--scenes` と校閲済みの `--captions` を渡す。単語列へDP整列し、保持区間内で語頭・語尾へ合わせる。出力の音声、見出し、画面切替、丸ワイプ、字幕を検品する。

## 画像Bロールの選び方

画像を挿入するときは、[画像レイアウトとガラスの確認](references/workflow.md#画像bロール)を読む。PNG・JPEG・HEICを `view:image` のシーンに指定する。HEICの向きはデコード時に反映する。imageシーンでは丸ワイプを使わない。

- 縦長のスクショ・SNS投稿・縦のグラフは `split`。人物2/5とガラス3/5に分け、カードは静止する。
- 縦の写真は `full`。ガラスの上の写真枠を固定し、中身だけ等速で1.00→1.04に拡大する。
- 横長のWeb画面・製品ページは `contain`。画像全体を収め、等速で1.00→1.04に拡大する。

**人物は目線の反対側、素材は目線の先に置く。** カメラ1フレームで向きを確認してから `image.presenter_side` を決める。画面右を向いて話すなら `left`。切り出し中心は `image.presenter_center_x` で調整する。

cutとシーン表の準備後に `glass-preview --scenes <シーン表>` を実行し、`work/images/glass-full.png` と `source-crop-check.png` を画像として確認する。ガラスの中に人物・肩・腕や物の形が残る場合は `image.glass_source_x` を人物のいない範囲に直して再生成する。静止画1枚を使い、ガラス自体は動かさない。人物素材がなければ生成り色と粒子のガラスを使う。

image中も有効な見出しを表示し、字幕は画面全体の中央に置く。imageと人物／画面の境目だけフェードし、image同士はカットする。SEは追加しない。見せ方を大きく変えるときは30秒前後の音付き試作で確認してから全編へ進む。

## 試作から本編へ

試作の採用後、`<out>/settings.json` を保持して本編へ展開する。「これでフル」など既存の承認があれば、同じ確認を繰り返さない。試作だけの依頼では本編を追加制作しない。

本編用の保持区間・シーン表・校正字幕を用意し、`full --settings <採用設定> --keep <本編区間> --scenes <本編シーン> --captions <本編校正字幕>` を使う。`full` は保持区間・素材内容・同期・設定のハッシュが前回cutと同じで中間ファイルが残っていればcutを再利用する。`--force` は再生成する。`--captions` を省くと初稿が再生成されるため、完成書き出しでは必ず指定する。`qc.json` の `caption.fail_count` が0になるまで修正する。本編の全文校正を終えていない場合、その事実を記録する。試作の40秒分の保持区間や字幕を本編へ流用しない。

「次回は前回と同じ設定で」は利用者から前回の `settings.json` を受け取り、`--settings` に渡す。新しい素材の同期値を過去案件から流用しない。主音声も案件ごとに判定し直す。前回設定に明示指定の `audio.master` が残っていて今回の指定がなければ `auto` に戻す。

## 共通の調整と納品

位置は右下／左下、大きさは標準／小さめ、字幕色を設定で変えられる。円形ワイプは実際の人物動画のクロップ。人物素材がなければワイプを省き、架空の人物を生成しない。大きな人物と同じ人物の丸ワイプを同時に出さない。既定では画面表示中に見出し帯を休止する。人物素材がない場合は画面表示中も帯を出し、画面上端を帯の下へ下げる。見出しは `heading.position`（left/right）・`bg_color`・`text_color`・`style:slant_band` を設定できる。最終映像の `output.video_bitrate` は既定8M。

目標の10〜15分に合わせて意味を削ったり、不足した内容を作り足したりしない。素材が不足する場合は到達可能な尺を伝える。

完成MP4そのものを検品し、MP4、SRT、採用設定、素材と時刻の対応、検品記録を納める。実施していない検査は未実施と記す。`qc.json` の技術PASSを、聴感確認・全文校正・通し視聴の完了と混同しない。

BGM/SE・図解の大量追加・サムネ・冒頭ダイジェスト・記事化用音声・投稿は、今回求められたものだけ扱う。外部投稿やメッセージ送信を自動実行しない。
