# 🐦 ダンドリ — 家の段取りボード

家族の共有カレンダーではなく、**家を回すための段取りボード**。
詳細は自分だけ、段取りは家族だけ。

## 設計原則（変更不可の3本柱）

1. **家族は入力しない。返事するだけ。** ダンドリの方から聞きに来て、ボタン1タップで完了する。登録する人は家庭に1人でいい
2. **平和な日は、鳥は黙る。** 各自が曜日別のデフォルト（夕飯いる/いらん・帰宅目安・弁当）を持ち、ダンドリが扱うのは**例外と未確定だけ**
3. **リマインドは、お母さんに集めない。** 通知は担当者本人へ直行。担当未定のものだけ家族に募集を出し、最初に【引き受ける】を押した人で確定する

## いまの状態（スプリント1）

段取りボードの画面が**ダミーデータで動く**ところまで。DBもLINEもまだ繋いでいない。

- 今日 / 明日 / 今週 の3タブ（月間カレンダーUIは作らない）
- 「まず、これ」＝**期限超過・担当未定・未回答**を最優先で最上部に出す
- 夕飯カード（曜日デフォルト＋その日の例外から人数を自動計算。未回答は赤＋いる/いらんボタン）
- タスク（担当者アバター／【引き受ける】【やった】／プリントOCR由来のタグ）
- 予定（他人のプライベート予定は「外出（帰り23時ごろ）」のような抽象表示に自動で置き換わる）
- 画面下の「いま見てる人」で**メンバーを切り替えると見え方が変わる**（プライバシー分離の確認用）

操作しても保存はされない（リロードで戻る）。

## 動かす

```bash
npm install
npm run dev      # http://localhost:3000
```

Vercel にそのまま載る（環境変数なし・ビルドコマンドはデフォルト）。

## 構成

```
app/
  page.tsx          サーバー側で「今日」を確定してダミーデータを組み立てる
  layout.tsx
  globals.css       モバイル1カラム前提の手書きCSS（UIライブラリ非依存）
components/
  Board.tsx         状態と操作（返事・引き受ける・やった）
  DayView.tsx       1日ぶんの表示
  DinnerCard.tsx    夕飯カード
  Avatar.tsx
lib/
  types.ts          ドメイン型（schema.sql と1対1）
  date.ts           日付ユーティリティ（すべて Asia/Tokyo 基準）
  board.ts          スナップショット → ボードの導出（Reactに依存しない純関数）
  dummy.ts          平井家のダミーデータ（今日からの相対で生成）
supabase/
  schema.sql        テーブル定義
```

`lib/board.ts` は React に一切依存していない。通知エンジン（スプリント3）が
「何を誰にいつ送るか」を決めるときに同じ関数を使うため。

## 次のスプリント

- **2:** Supabase 接続（schema.sql 適用・LIFFログイン・RLS）＋ 初期設定ウィザード（曜日デフォルト必須入力）
- **3:** LINE Webhook・グループ招待でのメンバー紐付け（postbackのgroupId+userIdを在籍証明に使う）・会話クエリ
- **4:** 通知エンジン（担当者直行ルーティング／Push通数の予算管理）＋ 行事プリントOCR

## 費用の前提（設計に効くので忘れない）

- LINEの **Push は受信人数分カウント**（30人グループへ5回送信＝150通消費の実測あり）。**Reply は無料・無制限**
- 無料版＝reply型（ダンドリは自分から喋らない）。**「鳥が自分からさえずるのは有料」が課金の柵**
- 有料家庭の想定は月100通前後＝原価100〜150円/家庭
