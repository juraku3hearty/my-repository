# X記事生成スキル

## 概要
ジャンルとターゲットに合わせたX記事（長文投稿）を生成する

## ワークフロー
1. CLAUDE.mdの自社情報からジャンル・ターゲットを確認
2. ユーザーに確認した上で、テーマ案を10個提案
3. ユーザーが1つ選択
4. 6つの型を組み込んだ記事を生成（8,000〜10,000字）

## 6つの型

### ① タップ設計
- タイトル：数字＋簡易性＋絶大な効果
  - 数字（例：「151万インプ」「3つの方法」）
  - 簡易性（例：「小学生でもわかる」「コピペ1回」）
  - 絶大な効果（例：「完全自動化」「月100万」）
- サムネ：タイトルのキーワードを視覚化、シリーズ感のある統一デザイン、タイムラインで埋もれない配色（黒×黄、赤×黒など）
- 冒頭3行：あるある型 or 実例提示型 or 言い切り型
  - あるある型：共感＋問題定義
  - 実例提示型：ありえない事実を見せる
  - 言い切り型：差別化を宣言する
- ※タイムラインに表示されるのは本文の最初の3行だけ。ここでタップされるか決まる

### ② 冒頭フック
- 共感 → 問題定義 → 立場宣言 の順
  - 共感：「最近Xで○○の記事めちゃくちゃ流れてきますよね」
  - 問題定義：「でも正直どれもめちゃくちゃ難しくないですか？」
  - 立場宣言：「だから僕（私）がこの記事を作りました」

### ③ 特徴宣言
- 「この記事はこういう記事です」を明示
- 「この記事を読むとこうなります」を約束
- 例：「選択肢を提示しません。『これをやってください』だけ」「専門用語は全部その場で説明します」「コピペする部分は全て矢印↓で示します」「100%できます。保証します」

### ④ STEP設計
- 「やることは○つだけ」で心理ハードルを下げる
- 手順を迷わせない構成
- 「なぜこれをやるのか」を全STEPに添える（理解を伴わない作業は続かない）
- 困ったときの解決方法を入れる（エラーが起きそうなポイントは先回りで潰す）

### ⑤ CTA設計
- プレゼントは1個に絞る（複数並べると行動率が落ちる）
- 「絶対に欲しい」プレゼントを設計する
- オプチャ→LINEの2段階導線
  - オープンチャット → 公式LINE友だち追加 → キーワード送信 → 自動配布
  - 理由：公式LINEはBANリスクがある／オープンチャットはBANリスクなし＋送信コスト0

### ⑥ 回遊構造
- 記事の最後に「次の記事」を貼る
- 関連する過去の記事を貼る
- 「フォローよろしくお願いします」
- 「引用で感想いただければ全リポストします」
- 効果：滞在時間が伸びる／フォロワー転換率が上がる／アルゴリズム評価が上がる／CTA到達者が増える

## 鉄則
感情→論理→簡単さ。この順番を守る

## 文体ルール

**※ 本人の実際の文体を `docs/x-articles/_buntai-rule-mayu.md` に実データから抽出済み。
書く前に必ず読む。以下の型の文体ルールのうち、衝突する2項目は本人側を優先する。**

- 1文は短く。改行多用。スマホスクロール前提（一致）
- 専門用語は初出時に必ず1行で説明（一致）
- ~~丁寧語ベースだがカジュアルで熱量が高い~~
  → **熱量より「トゲを抜く」。断定を落とし「〜と思っています」で締める**
- ~~読者に選択肢を与えない。「これをやってください」だけ~~
  → **「全部やらなくて大丈夫です。まずはどれかひとつ」とハードルを下げる**

### 本人の文体の要点（詳細は上記ファイル）
1. **事実を捏造しない**（業者案には長男→実際は次女、等の誤りが混入していた実績あり）
2. **他人を断罪しない。** 「〜な人は置いていかれる／用済み」は禁止。批判したくなったら自分の過去として書く
3. **誇張・断定を落とす**（「10倍」「劇的」「絶対」「〜だけです」を避ける）
4. **自慢にしない。** 褒められた話より、自分が言っていた言葉
5. **劇的なセリフを作らない。** 実際に言われた普通の一言を置く。重い場面は「ｗ」で抜く
6. **固有の記憶を足す**（百貨店で半泣きでお詫びの手紙／中3と高3のダブル受験 等）
7. **過去を否定しない。** 裏方の15年は克服した過去ではなく資産として書く
8. 絵文字は😊😂を1投稿に1〜2個。自嘲に「w」

## このアカウント固有の設定（famitect / LUXTEIR）

正本は `docs/famitect-business-profile.md`。記事を書く前に必ず読む。以下は記事生成時の運用ルール。

### Xの位置づけ（重要・型の前提を上書きする）
事業設計上、Xは「紹介されたあとに何の人か確認する場所」。集客の主役ではない。
したがってX記事の目的は**バズではなく、次の2つだけ**。

1. 紹介・DM・Facebook経由で名前を知った社長が読んだときに「この人に相談できる」と分かる状態にする
2. 紹介パートナー（税理士・社労士・制作会社・Web会社・予約システム導入支援者）が「あの人に振ろう」と思える材料を置く

数字（インプ・フォロワー）を記事の成功指標にしない。指標は「30分の“めんどくさいこと相談”が入ったか」。

### ジャンル
小規模事業の業務仕組み化。社長依存の解消。AI・自動化は手段として扱う（目的にしない）。

### ターゲット読者
従業員1〜10名の店舗業・サービス業の社長。裏方業務と判断が社長に集中している人。
**記事内では必ず2種のペルソナを拾う**：
- 初心者＝仕組み化に本格着手した経験がない。「自分でやった方が早い」
- 経験者＝マニュアル・ツール・外注を試したが「作ったのに使われない」「判断だけ戻ってくる」

### トーン
- カジュアル丁寧語。関西のニュアンス（「〜やん」「〜んやろか」）は社長の心の声の引用部分にだけ使う。地の文は標準語
- 「教える人」ではなく「会社の裏側に入って一緒に手を動かす人」の距離感
- 煽らない。「月100万」「完全自動化」系の誇張は使わない（信念と衝突する）
- 経験者の過去の失敗を否定しない。「やり方が悪かった」ではなく「現場とズレてた」と書く

### 記事で使える実績素材
- 小規模事業の裏方実務15年以上（経理・人事・広告・現場・業務整理を横断）
- 受注側と発注側の両方を経験している
- コード経験ゼロからAI自動化を導入し、3業種6事業所で稼働中
- 100チャレ（AI自動化を100人に無料提供）の実例
  - No.1 献立AI（LINE Bot × GAS × Gemini）
  - No.2 タイムカードOCR＋VBA転記（弁護士の未払給料裁判案件）
  - No.3 YouTube自動アップロード（本番稼働中）
- ※「お客様の声」は現在準備中。**捏造しない。**実績として書けるのは上記と自院運用のみ

### 主張の軸（記事の論理パートで使う）
- 仕事を渡すときに作業手順だけ伝えても、社長が無意識にやっている**判断**が渡っていないから戻ってくる
- だから手順書ではなく「判断基準」を言語化する
- 全部を一気に変えず「どこを外すと一番効くか」を1業務だけ見立てる
- 資料を納品して終わりにせず、**スタッフが実際に一度回して**詰まりを直してから完成にする
- 外部の支援者自身が新しい属人化の原因になってはいけない。手順・データ・アカウントは会社側に残す
- まずGAS・LINE・スプレッドシートで足りるか検討する。紙のチェックリストで十分ならそれを選ぶ

### ④STEP設計の扱い
読者は社長であって作業者ではない。「コピペして動かす」手順記事にしない。
STEPは**社長が自分の会社でできる棚卸しの手順**として書く。例：
1. 今週「自分にしか聞けない質問」が来た回数を数える
2. その中で一番多かった業務を1つだけ選ぶ
3. その業務で自分が無意識にやっている確認を書き出す
4. スタッフに一度渡して、止まった場所をメモする

### ⑤CTA設計（型のオプチャ→LINE導線を事業に合わせて改変）
型の原則「プレゼントは1個に絞る」「2段階導線」は守る。ただし配布先は情報発信用リストではなく**30分の相談枠**に接続する。

- プレゼント（記事ごとに**1個だけ**選ぶ）
  - 「社長の頭の中を書き出す棚卸しシート」（1業務分）
  - 「スタッフに渡す前チェックリスト（判断基準の言語化用）」
  - 100チャレ無料枠
- 導線：**X記事 → 公式LINE → キーワード送信 → シート自動配布 → 30分「めんどくさいこと相談」→ 見立て → 提案書**
- **オープンチャットは挟まない（型から変更）**
  - 型が挟む理由はBANリスク回避と送信コスト0。どちらも大量配信しないMAYUには該当しない
  - Xの流入がほぼ無い（3ヶ月でURLクリック2回）ので、溜めるリスト自体が発生していない
  - 紹介で来た人に「まずオプチャへ」は摩擦。情報発信者の導線に見えると66,000円の個別伴走では信用が下がる
- **2段階の意味が型とは違う。** 型＝リストを守る2段階／MAYU＝**いきなり相談させない2段階**（シートを使ってもらってから相談へ）
- 価格は記事内で売り込まない。入口66,000円は相談後の提案書で出す
- 「代行します」とは書かない。**「社長の手から外す形にします」**と書く
- **紹介パートナー向け記事では紹介料に触れない。** 本人未決定かつ相手に既存の慣習がある可能性があるため。
  代わりに「税務・労務・制作が必要な場面ではこちらからお願いする」という相互紹介の事実だけ書く

### ⑥回遊構造
次の記事・過去記事・フォロー訴求・「引用で感想いただければ全リポストします」は型どおり。
加えて**紹介パートナー向けの一行**を置く：「周りに“社長が全部抱えてる”会社があれば、この記事を渡してもらえると助かります」
