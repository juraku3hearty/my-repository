# X投稿 文体ツール セットアップ

過去の「業者さんの雛形」と「自分の書き換え」の差分から文体ルールを取り出し、
以後はその文体で投稿案を出すツールです。

**狙いは業者さんの再現ではありません。書き直す工程をなくすことです。**

---

## 前提にしているシートの形

A列にラベルが縦に繰り返し、**B〜H列が1週間分**（1列＝1日＝1投稿）。

```
        B          C      D      E      F      G      H
日付    月         火     水     木     金     土     日
投稿日  2026-10-19 …
投稿文  ← 業者さんの雛形
修正欄  ← 自分の書き換え
（空白行）
日付    ← 次の週のブロック
```

列の位置やラベル名が違っても、`X_設定` シートで変更できます。
1行目が見出しの普通の表でも動きます（`レイアウト` を「表（横）」にする）。

---

## ファイル構成

| ファイル | 役割 |
|---|---|
| `10_XConfig.js` | 設定・モデル・シート名 |
| `11_XClaude.js` | Claude API（UrlFetchApp。GASはSDKが使えないので素のHTTP） |
| `12_XMap.js` | シートの読み取り（週ブロック／表の両対応） |
| `13_XExtract.js` | 文体ルールの抽出（バッチ・再開可） |
| `14_XGenerate.js` | 投稿案の生成＋週ブロック形式での書き出し |
| `15_XMenu.js` | スプレッドシートのメニュー |

モデルは **`claude-opus-5-5`**。文体の再現が目的なので、安いモデルには落としていません。

## セットアップ

### 1. スクリプトを過去ログのスプレッドシートに入れる

スプレッドシートを開く → 拡張機能 → Apps Script → `10_`〜`15_` のファイルを貼る。

（別プロジェクトで動かす場合は、スクリプトプロパティ `X_SPREADSHEET_ID` に
過去ログのスプレッドシートIDを設定してください）

### 2. APIキーを設定する

プロジェクトの設定 → スクリプト プロパティ

| キー | 値 |
|---|---|
| `ANTHROPIC_API_KEY` | Claude APIキー |

### 3. メニューから順に実行する

シートを開き直すと「**X 文体ツール**」メニューが出ます。

| 手順 | メニュー | 内容 |
|---|---|---|
| ① | 設定シートを作る / 更新する | `X_設定` が作られ、レイアウトと列を自動推測して埋めます |
| ①' | 読み取れるか確認する | 何件読めたかをログに出します。**ここが0件なら設定を直す** |
| ② | 文体を抽出する | 12件ずつ処理。時間切れで止まったら**もう一度押す**と続きから |
| ③ | 今週の投稿案を作る | テーマと本数を聞いて生成 |

---

## ① の前に、`X_設定` で必ず埋めるもの

| 項目 | 内容 |
|---|---|
| 対象シート名 | 過去ログのシート名 |
| レイアウト | `ブロック（縦）` または `表（横）` |
| ▼値の開始列 / ▼値の終了列 | 既定は B と H（1週間7日） |
| **これからのコンセプト** | **ここが空だと生成できません。**内容はここだけから作ります |

`アカウント紹介` `投稿の方向性` `扱わないこと` は任意ですが、
入れるほど生成の精度が上がります。

---

## ② 文体抽出で何を取り出しているか

雛形と実投稿を並べて、AIに差分を読ませます。

| 取り出すもの | 意味 |
|---|---|
| **禁止語** | 業者さんが書いたのに、自分が消した語。**これが一番重要** |
| 採用語 | 雛形になく、自分が足した語 |
| 文の長さ / 改行 / 語尾 / 一人称 | 形の特徴 |
| 冒頭パターン / CTAパターン | 入り方と締め方 |

結果は `X_文体ルール` シートに出ます。**手で直せます。**
生成時はシートの内容を読むので、直した内容がそのまま効きます。

AIには**本文を書き換えさせていません。**判定と抽出だけです。

## ③ 生成の出力

2か所に出ます。

| シート | 用途 |
|---|---|
| `X_投稿案` | 1行1投稿。枠・役割・投稿の狙い・元になった返信・本文・事実確認が必要な箇所・編集メモが並ぶ |
| `X_投稿案_週形式` | **いつものシートと同じ週ブロック形式。**そのままコピーして貼れる |

### 流れ：企画 → 執筆 → 編集

**1週間に同じ主張は原則1本**です。長文と短文で同じ主張を言い直すのも「2本」と数えます。
短文は長文の切り出しではなく、1つの主張を1つの具体例で短く書くものです。

1. **企画**：書く前に7本ぶんの企画を1回で決める。1本ごとに「使う返信（R番号）・今週あったこと（M番号）」「題材」「主張」を割り当てる。
   同じ主張・同じ材料・同じ出来事の返信は1本にまとめる
2. **執筆**：企画どおりに並列で書く。他の本の主張と材料は「言わない・使わない」として渡す
3. **編集**：並べて重なりを確認する（下記）

### 週全体の編集

7本を書いたあと、並べて重なりを確認します（テーマ・主張・エピソード・読後感）。

1. 重なったグループからは、最も良い1本だけを残す
2. 外した枠は、今週の返信・引用のうち**まだ使っていないもの**から作り直す
3. 作り直した分がまだ重なっていれば、その枠は空ける
4. 材料が無い枠は、**題材を変えて**叩き台を作る（これからやりたい仕事 → 仕事の考え方 → 実務の視点 → 人柄 → 日常の気づき の順に、残す本に無い題材）。
   事業の方向性シートは**軸の確認だけ**に使い、そこからテーマは作らない。
   `X_設定` の「材料が無い枠」を `空ける` にすると、作らずに**空き**にして報告する
5. 業務改善・仕組み化の話は週2本まで。多ければ「題材の偏り」として作り直す
6. 「まだ実績が無いことを実績のように書いている」「材料に無い発言を書いている」箇所を挙げ、
   `事実確認が必要な箇所` に「言い過ぎの可能性」として書く（本文は直さない）

### 書き方のルール

- 実際に経験したことは過去形。これから大切にしたい仕事の進め方は「こうしたい」「こう考えている」
- 実績、相談者・お客様・スタッフの発言は創作しない。カギカッコの言葉は材料にあるものだけ
- **本文に【要確認】を残さない。**確認済みの事実だけで完成させ、実例が無ければ考え方・方針として書く。
  それでも確かめたいことは、本文とは別に `事実確認が必要な箇所` に質問として書く

`編集メモ` 列に「どの重なりから残したか」「どの返信（R番号）から作り直したか」が入ります。

自分で選びたいときは **「④ 選んだ本を残して、残りを作り直す」** を押し、残す番号を入れます（例: `1,2,4`）。

### 状態

| 状態 | 意味 |
|---|---|
| 未 | 叩き台 |
| 質問あり | 本文は完成している。`事実確認が必要な箇所` にあなたへの質問がある。週形式の見出しに「（質問あり）」 |
| 要確認 | 本文に【要確認：…】が残ってしまった（ルール違反）。**完成稿として扱わない**。週形式の見出しに「（要確認・未完成）」 |
| 残す | 「残して作り直す」で残した本 |
| 空き | 材料が無くて作らなかった枠（「材料が無い枠」= 空ける のとき） |

【要確認】を埋めてから「投稿案を自動チェックする」を押すと、状態は「未」に戻ります。

週形式では、生成した本文が `投稿文` の行に入り、`修正欄` は空です。
直したいときだけ `修正欄` を使ってください。**その差分が、次回の抽出の材料になります。**

## 設計上の約束

### 材料は3つ。過去の投稿は「数字」だけ使う

| 材料 | 使い方 |
|---|---|
| ① 外部ライターの企画シート・型カタログ | テーマの選び方・切り口の作り方だけを参考にする |
| ② 直近7日の返信・引用・今週あったこと | **いちばんの材料** |
| ③ 事業の方向性シート | 誰に向けた発信かの判断に使う |

過去の投稿の**本文**は渡しません（中身まで引っぱられて焼き直しになるため）。
文体は `X_文体ルール` に取り出してあるので、それだけで書きます。
`X_設定` の「過去の投稿・経歴を材料にする」を `はい` にすると戻せます。

過去の投稿の**数字**は「アナリティクス: 伸びる系統を調べる」で使います。
役割・分類ごとに、インプレッションの中央値と、返信・フォロー・プロフィールへのアクセスを比べ、
`X_系統の傾向` に出します。投稿案には系統ごとの数字だけを渡します。

### AIに本文を書き換えさせない

抽出は判定だけ。生成は新規作成だけ。
過去の投稿をAIに「整える」ことはしません。

### 禁止語を最優先のルールにしている

生成のシステムプロンプトで、禁止語を最上位の制約にしています。
`X_文体ルール` の禁止語を手で足せば、すぐ効きます。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 読み取り0件 | `X_設定` の `対象シート名` `レイアウト` `▼ラベル列` `▼値の開始列/終了列` を確認。`読み取れるか確認する` のログを見る |
| 7本が1本に混ざる | `▼値の終了列` が未設定。`H` を入れる |
| 抽出が途中で止まる | 正常。**もう一度「文体を抽出する」を押す**と続きから |
| 最初からやり直したい | 「抽出をやり直す」→「文体を抽出する」 |
| 生成が止まる | `これからのコンセプト` が空。`X_設定` に入れる |
| 7本にならない | `X_設定` の「材料が無い枠」が `空ける` になっている。`方向性から作る` に戻すか、「残して作り直す」で今週あったことを足す |
| 文体が似ていない | `X_文体ルール` の禁止語を手で足す。1語足すだけでかなり変わる |
