## 1. 確定コンセプト

```
AIで仕事を受けたい人へ｜非エンジニアが調べ方と聞き方だけで作る
「LINEに送るだけ」の業務自動化を、3業種に導入した経験から発信します
```

約70文字。要素は「誰に／何について／どんな立場から」＋実績。

| 要素 | 内容 |
|---|---|
| 読者 | AIで仕事を受けたい人（Xにいる稼ぎたい層。Brainで金を払う層） |
| 軸（思想） | アプリを増やさない／相手が普段使っている道具の中で完結させる |
| 成果物（表） | LINEに送るだけで動く業務自動化 |
| 再現性（核） | 調べ方と聞き方（＝切り口を変える力） |
| 立場 | 非エンジニア・独学 |
| 運用 | 別人格（本業・実名・家族と紐づけない。安全上の理由あり） |

### 3層構造（順序を崩さない）

```
表（見せる）     LINEに送るだけで動く自動化   ← 誰でも分かる／興味を持たせる
中（証明）       GAS・スプレッドシート        ← 作れる証明
核（なぜできた） 切り口を変えて探す・聞く力    ← 再現性・唯一の差別化
```

| 層 | 出る場所 |
|---|---|
| 表：LINE | コンセプト／プロフィール1行目／タイトル／サムネ |
| 中：GAS | 本文の後半／特典の中身 |
| 核：調べ方と聞き方 | コンセプト／プロフィール3要素目／記事の中盤以降／特典の設計思想 |

**順序の理由**
- 別人格は実名の信頼が使えないため、信頼を作る手段は成果物しかない。GASは隠さず後半で必ず出す
- 核だけを看板にすると成果物が消え、「プロンプトの書き方」という激戦区に入る
- 核がないと「非エンジニアが作れました」は再現性のない自慢で終わる

### 却下した案と理由

| 案 | 却下理由 |
|---|---|
| AI×業務効率化 | 成果物が見えない。「AI」と同じ広さ |
| AI×副業で稼ぐ | 匿名 × 「稼げます」は最も信用されない組み合わせ。実践在庫が全部使えなくなる |
| AI×GAS（GASを表に） | 読者がGASという言葉を知らない。入り口として機能しない |
| AI×整骨院の業務自動化 | 絞りすぎ。他2件の実績が軸から外れる |
| PCが苦手な事業者向け | **Brainを買わない層**。第4〜7章が成立しない（詳細は6章） |
| 「自分の店」を含む表現 | 事実と不一致（オーナーではない）＋ 家族の事業と結びつく |

## 2. サブコンセプト（動機）

**経済的に自立する必要があるという動機。** 発信の背景としてのみ使う。

### 置き場所

| 場所 | 扱い |
|---|---|
| コンセプト1行 | **入れない**（成果物が消え、読者が「境遇が同じ人」に変わる） |
| プロフィール3要素目 | **事情は書かない**。姿勢だけ置く |
| ストーリー型記事（第9章の型） | **ここが本命。1〜2本で深く書く** |
| 全記事の通奏低音 | 「なぜ自分で稼ぐ必要があるのか」として効く |

**プロフィールではなく記事に置く理由**：プロフィールは常時表示・全ポストに付随し、消しても引用やスクショが残る。露出面が最大。記事なら1本に限定できて、効果はむしろ大きい。

### 表現の強度

| | 書き方 | 強さ | 特定リスク | 判定 |
|---|---|---|---|---|
| A | 直接的に事情を書く | 最強 | 高 | 使わない |
| B | 「働きながら、自分の収入を作る必要があった」 | 強い | 中 | **記事でのみ使用** |
| C | 「自分の収入が必要だった」 | 中 | 低 | 記事の冒頭向き |

プロフィール3要素目に入れる文（事情を含まない版）：
```
専門知識がなくても、調べ方と聞き方だけで作れると伝えたい
```

### 参考：同じ構造の先例
メルおじ氏の「手取り16万／漢字ドリル／貯金39,163円」も、**コンセプトには入っていない**。
冒頭とストーリーで使い、コンセプトは「AI × X丸投げ顧問」のまま。あれが正しい配置。

## 3. 実践在庫（一次情報）

匿名運用のため、顧客・勤務先・家族・地域の固有名詞は出さない。

| 案件 | 届けた場所 | 新しく覚えさせたもの | 匿名で書くときの表現 |
|---|---|---|---|
| 献立AI（LINE Bot × GAS × Gemini） | **LINE** | なし | 「LINEで送ると献立と買い物リストが返ってくる仕組み」 |
| タイムカードOCR → 既存Excelへ転記 | **相手が既に使っていたExcel** | なし | 「画像から勤務時間を読み取り、相手が既に使っていたExcelにそのまま転記」 |
| 動画の自動アップロード | **Webフォーム** | なし | 「フォームから投げると自動でアップロードされる仕組み」 |
| AI環境の構築と月額保守 | **顧客のDiscord** | なし | 「AI環境の構築と保守を月額で継続提供」 |
| 3業種への導入 | LINE中心 | なし | 「3業種に導入して運用中」 |

### 最強の一枚
**タイムカードOCR → 既存Excel転記**。提出用Excelのフォーマットを1ミリも変えず流し込んだ。
新しい画面を作れば実装は楽なのに作らなかった＝**思想が先にある証拠**。そのまま記事になる。

### 人からよく相談されること（＝需要の外部証拠）

他人が繰り返し聞いてくること。自己申告の実績と違い、**需要の裏付けがある唯一の項目**。

- 「どうやって調べるの？」「どうやってやってるの？」
- （AI以前から）「どこで売ってるの？」「なんで見つけられるの？」

**内容**：検索で打ち込む語の選び方が独特で、みんなが見つけられないものを切り口を変えて引っかけるのが得意。

**AI時代における意味**：検索の切り口を変える力 ＝ プロンプトの切り口を変える力。対象が変わっただけで能力は同一。
AI界の発信の大半は「プロンプト集」＝答えを渡す形で、切り口の作り方を渡す発信はほぼない → 被らない。

**読者との接続**：作れない原因は技術ではなく「詰まったときに何を聞けばいいか分からない」ところ。
「スキルがないから作れない」→ **「調べ方と聞き方で埋まる」**（独学・非エンジニアで4件＋3業種導入という実証つき）。

### 自分の型（5事例に共通する1本の才能）

| やったこと | 形 |
|---|---|
| 検索（AI以前） | 既にWEBにある情報を、切り口を変えて引っかける |
| タイムカードOCR | 既にあるExcelを変えずに流し込む |
| LINE自動化 | 既に全員が入っているアプリの中で完結させる |
| 月額保守 | 既に顧客が持つ環境を使わせる（自分は抱えない） |
| 100チャレ | 既にある他人の業務課題を材料にする |

**「新しく作らない。既にあるものを見つけて、繋ぎ替える」** ＝ 同じ原理を対象を変えて適用しているだけ。
AI以前から同じことをやっているので、ツールが変わっても残る。

## 4. 実績の書き方（3-5準拠）

### 出す / 出さない

| 実績 | 判断 | 理由 |
|---|---|---|
| 3業種に導入して運用中 | **出す** | 金額不要で最も強い。「試作」ではなく「稼働」 |
| 制作4件 | 出す | 「制作」と明記 |
| 月額保守を継続提供 | 出す（社数は要確定） | 金額は小さく見えるので前面に出さない |
| **ツール解約による削減額** | **出さない** | 家族の事業の支出。業種と併せると特定される |
| 勤務先・家族への言及 | **出さない** | 同上 |

### 「導入」と「受託」の使い分け

| 書き方 | 使える数 | 根拠 |
|---|---|---|
| 「3業種に**導入**」「3業種で**運用中**」 | 3 | 運用しているのは事実 |
| 「**受託**」「**納品**」「受注」 | 2 | 自分が働く店は売上が発生していない |

### 混同しないもの
- 売上 / 利益 / 削減額 / 紹介報酬 は全部別
- 初期料金と継続料金は別の数字（混ぜない）
- 期間合計を月間に変えない。月額を年額に膨らませない
- 「読んだ / 試した / 作った / 導入した / 運用中 / 売れた」を区別する

## 5. 入り口の在庫（複数・自由・広い）

コンセプトは固定したまま、話の始め方は変えていい（講座 2-6）。

**① 稼ぐ側の悩み（Xの読者の大半）**
- AI案件が単発で終わって、毎月ゼロから営業している
- 単価が上がらない
- アプリが作れないから案件を受けられない

**② 作業の悩み**
- 毎月同じ転記作業をしている
- 紙や画像から数字を手で打ち込んでいる
- 毎月払っているツール代が減らない

**③ AI活用の悩み**
- ChatGPTを使っているけど仕事につながらない
- エラーが出た瞬間に手が止まる
- ツールを増やしたのに結局手作業が残っている

### 判定基準

> **その記事の後半に、自分の実践か作った仕組みが出てくるか。**

出てこないなら入り口ではなく**脱線**。

| | 判定 |
|---|---|
| 「時間管理術」から入って、最後に作った仕組みを見せる | ◯ 入り口 |
| 「時間管理術」の話で終わる | ✗ 脱線 |
| 「AI副業の稼ぎ方」から入って、月額化の設計に着地 | ◯ 入り口 |
| 「AI副業の稼ぎ方」一般論で終わる | ✗ 脱線（差別化ゼロの激戦区） |

## 6. なぜ「事業者向け」を却下したか（再検討時に読む）

別のAIに文脈なしで聞くと、必ず「PCが苦手な小さなお店・事業者向け」が返ってくる。
**サービスのコンセプトとしてはそれが正しい**が、Brainアフィとは接続しない。

| | Brainアフィ | SaaS販売（本命） |
|---|---|---|
| 客 | AIで稼ぎたい人 | PCが苦手な事業者 |
| 売り物 | 教材の紹介＋特典 | 受託・月額保守 |
| 獲る場所 | **X** | **紹介・地域・業界コミュニティ** |
| 速度 | 速い | 遅い |

### 事業者がBrainを買わない理由
1. Brainの存在を知らない（情報商材プラットフォームは発信者界の内輪の常識）
2. PCが苦手＝決済・ログイン・ドキュメント操作が障壁
3. 買う動機が違う。欲しいのは「やってもらう」こと → 教材ではなく受託を買う
4. 「情報商材」への警戒感がある層

※ 同じ人が、受託には10万円出しても教材には5,000円出さない。購買行動が別物。

### 実績は一方向にしか流れない
```
事業者への導入実績 ──→ 稼ぎたい人への「作れる証明」  ◯ 効く
稼ぎたい人向けの発信 ──→ 事業者の信用               ✗ ほぼ効かない
```
**素材は本命事業から取って、Xでは稼ぎたい人に売る。** SaaS側の活動がX側のネタ供給になる。

### もし事業者向けに戻す場合
講座を「Brainを売る手順書」ではなく「LINEで顧客に届ける仕組みの手順書」として使う。
第4〜5章（Brain選定・感想）だけ飛ばし、第6章（特典→無料お試し）、第7章（公式LINE→サポート窓口）、
第9〜11章（記事→導入事例・説明資料）、第11章（オープンチャット→導入店サポート）、
第12章（配信→既存顧客への追加提案）を転用する。

## 7. 記事の展開パターン

### 例A：稼ぐ側の入り口 × 月額化への着地（実績・思想型）
```
入り口   「AI案件、納品して終わりで毎月ゼロから営業してませんか」
  ↓
一次情報 作った仕組みを納品して終わりにせず、保守として月額で受けた
  ↓
なぜ    LINEで作ると相手の環境に残る → 運用が続く → 保守が必要になる
  ↓
着地    だから最初からLINEの中で作る          ← コンセプト
  ↓
案内    自動化の設計チェックリスト（特典）
```

### 例B：作業の悩みの入り口 × 作れる証明への着地（ガイド型）
```
入り口   「毎月タイムカードを手で集計してませんか」
  ↓
一次情報 勤務時間の集計を自動化した案件（業種はぼかす）
  ↓
仕組み   画像 → OCR → 既にあるExcelに自動転記。新しい画面は作らない
  ↓
着地    普段使っている道具の中でここまでできる  ← コンセプト
  ↓
案内    テンプレ一式（特典）
```

### 例C：核を主題にした記事（診断・理論型）
```
入り口   「エラーが出た瞬間に手が止まりませんか」
  ↓
指摘    止まる原因は技術ではなく、何を聞けばいいか分からないこと
  ↓
一次情報 非エンジニアで作れた理由は、調べ方と聞き方だけ
  ↓
着地    切り口を変えて聞けば埋まる            ← 核
  ↓
案内    質問の切り口テンプレ（特典）
```

### 記事テーマのストック
- 「エラーが出たときAIに何を渡すか。画面をそのまま貼るだけで9割解決する」
- 「探せる人と探せない人の差は、知識じゃなくて打ち込む語の選び方」
- 「作り方が分からないものを作る手順。完成形から逆に聞いていく」
- 「AI案件を単発で終わらせない。LINEで作ると保守が発生する」
- 「毎月払ってるツール代、LINEとスプレッドシートで消せます」（※金額は出さない）
- ストーリー型1本（動機。表現強度B）

## 8. 特典の候補（第6章の掛け合わせ）

### 第一候補：**「詰まったときにAIへ投げる質問の切り口テンプレ」**

| 理由 | |
|---|---|
| 差別化 | プロンプト集（＝答えを渡す）ではなく**切り口を渡す**。AI界でほぼ被らない |
| 汎用性 | どんな商品と掛け合わせても成立 → 紹介商品が変わっても使い回せる |
| 需要の裏付け | 「どうやって調べるの」は実際に繰り返し相談されている内容 |
| 読者の障壁に直撃 | 作れない原因は技術ではなく「何を聞けばいいか分からない」ところ |

### 第二候補：**「公式LINEの応答メッセージで特典を自動配布する仕組み（LINE × GASテンプレ一式）」**

| 理由 | |
|---|---|
| 需要 | Brainアフィをやる全員が第7章で必要になる |
| 自分の強み | 普段やっていること。他の受講者は初めてで苦戦する箇所 |
| 副産物 | 講座の第7章を進める作業が、そのまま記事1本と特典1つになる |

※特典の価値は中層（GAS）と核（切り口）で出す。「LINEの使い方」だけだと価値が薄い。

## 9. 別人格の運用ルール

安全上の理由があるため、**講座の手順を1箇所だけ意図的に外す**。

### 講座 7-5 の例外（重要）
講座は「ビジネスIDの登録画面で『LINEアカウントで登録』を選び、**普段のLINEアカウント**で進めます」
と書いているが、**これをやると個人LINEに紐づく**。メールアドレスで別途ビジネスIDを作る。

### その他

| 項目 | 対応 |
|---|---|
| Xアカウント | **既存の里桜（rio-ai）を使用**。本人と無関係の人格として運用。過去の内容も軸に合うため新規作成しない。※1万インプは別の第三アカウントの数字。里桜の読者データはまだ無い |
| 匿名化の範囲 | **名前・アイコン・連絡先・語り口は切ってよい。実績・経験・数字は本人の事実のまま**（架空化しない。感想・特典が自分の実践に依拠するため、事実と切れた人格には書くものがなくなる） |
| 公式LINE・オープンチャット | この人格専用に新規作成。本業・既存と混ぜない |
| Googleアカウント | 別人格用を新規作成（特典配布ドキュメントに名前が出る） |
| X の連絡先 | 電話番号・メールを本人のものと分ける |
| Brainの売上受取 | 口座名義が表示される箇所がないか設定画面で確認 |
| 投稿時間帯 | 生活パターンが出る。予約投稿で消す |
| アカウント名・画像 | X / LINE / オープンチャット で統一（購入者が見分けられるように） |
| 表示名の語 | 本名の一部・店名・地名・既存アカウント名は使わない |
| 立場の書き方 | 「店舗の現場で働きながら」程度に抽象化。業種・地域・家族関係は出さない |
| 出さない情報 | 顧客名・連絡先・購入画面スクショ・勤務先・家族・ツール解約額 |

### 入り口での注意
LINE発信者の大半は「LINE公式アカウント × マーケ集客」（リスト取り・ステップ配信）。
自分がやるのは**業務そのものをLINEで動かす**（社内・現場用途）ので、最初の1行で区別を明示する。

```
✗ 「LINEを最大限使う方法」
◯ 「集客じゃなくて、業務そのものをLINEの中で終わらせる」
```

| 3行目 | 姿勢。**「失敗も出す」「動いているものだけ載せる」は約束**。試作は載せない |

**業種名は書かない**（他AIは「整骨院・ペットサロン・ネイルサロン」と出してきたが、知人に一発で特定される。動機記事とも両立しない）。
例外：里桜アカウントの過去ポストで既に業種を明かしている場合は再検討。

### 既存アカウントで 3-9 に入る前のチェック
1. 固定ポストを差し替える（100チャレ応募の導線は外す。新軸の投稿ができるまで固定なしで可）
2. 今のプロフィール文を他AIに渡す（3-7は「すでに使っているプロフィール文」を聞く設計）
3. アイコンは縮小表示で判別できれば変えない
4. 軸と矛盾する過去ポストは削除不要。最近の数件が新軸と合っていれば十分
5. 1万インプはプロフィールに書かない（表示回数は成果ではない。8-1／3-5）

### 判断の癖（自己メモ）
- **一つの否定的データで軸ごと捨てようとする傾向がある。**
  「1万インプで応募0」→「ジャンルが悪い」→「別軸へ」を1回で跳んだ。実際の原因はオファー設計だった。
  → **軸を疑う前に、受け皿を疑う。**
- 自己評価が証拠より低い。成果物を過小評価すると弱い選択肢に手が伸びる。
- 「自分が普通だと思っていること」（探し方・聞き方）が商品。そこを発信していないのが最大の機会損失。

## 11. 他のAIに渡すときのブロック

### コンセプト修正を伝える場合
```
コンセプトを次に修正しました。これを確定版として使ってください。

AIで仕事を受けたい人へ｜非エンジニアが調べ方と聞き方だけで作る
「LINEに送るだけ」の業務自動化を、3業種に導入した経験から発信します

修正理由：
・「自分の店」は削除。私はスタッフでオーナーではないため事実と合わない
・実績は「導入」なら3業種、「受託」なら2件。自分が働く店は売上が発生していないので受託には数えない
・金額（ツール解約による削減額）は出しません
・勤務先や家族に関する情報も出しません
```

### ゼロから状況を渡す場合
```
顧客の実名・業種、勤務先、家族に関する情報は出せない前提で整理してください。

軸：新しいアプリを作らず、相手が普段使っている道具（LINE・スプレッドシート・
    Excel）の中で業務を完結させる。表に出すのはLINE、中身はGAS。

実績：
・LINEで送ると献立と買い物リストが返ってくる仕組み
・画像から勤務時間を読み取り、相手が既に使っていたExcelにそのまま転記
・フォームから動画を投げると自動でアップロードされる仕組み
・AI環境の構築と保守を月額で継続提供
・3業種に導入して運用中（受託は2件。1件は自分が働く店なので売上は発生していない）

人からよく相談されること：
・「どうやって調べるの」「どうやってやってるの」
・AI以前から「どこで売ってるの」「なんで見つけられるの」
→ 検索の切り口を変えて、みんなが見つけられないものを引っかけるのが得意

読者：Xにいる「AIで仕事を受けたい人」
コンセプトは稼ぎ方ではなく、上記の軸に絞ってください。
「調べ方・聞き方」は再現性の根拠として扱い、看板にはしないでください。
金額の実績は使わないでください。
```
