# X投稿 叩き台ツールの仕組み（他のAIに渡す用）

この文書は、私（書き手）が使っている「X投稿の叩き台を作るツール」の仕組みをまとめたものです。
入力・生成ロジック・出力・評価と改善の4つに分けて書いています。
最後に、あなた（このAI）にお願いしたいことを書いています。

---

## 0. 前提

### 誰の、何のためのツールか

- 書き手：中小企業の社長と現場のあいだに入り、「社長語を、現場語に」翻訳する仕事をしている個人
- 目的：X（旧Twitter）の投稿を **週7本（長文2本・短文5本）**、本人が手を入れる前提の **叩き台** として作る
- 本人が時間を使いたいのは、他人の投稿へのコメント（AIにはできない、自分から人とつながる活動）。自分の投稿づくりは任せたい
- 以前は外部ライターから毎週の投稿案をもらい、本人が書き直して出していた（約6か月、毎日投稿）

### 動作環境

- Google スプレッドシート ＋ Google Apps Script（GAS）
- AI は Claude API（モデル：claude-opus-5-5）を GAS から HTTP で呼ぶ
- GAS には1回6分の実行制限がある

### 本人が決めたルール（最優先）

1. 1週間に **同じ主張は原則1本**。長文と短文で同じ主張を言い直すのも「2本」と数える
2. 1投稿1テーマ。複数のエピソードを1本に混ぜない
3. 実績、相談者・お客様・スタッフの発言、確認できない数字は **創作しない**
4. 実際に経験したことは過去形。これからやりたい仕事は「こうしたい」「こう考えている」と書き、実績のように書かない
5. 本人が言っていない因果関係や成果を付け加えない（「安心材料になる」を「成功する」にしない）
6. 業務改善・仕組み化の話は週2本まで。仕事の考え方・実務の視点・人柄・日常の気づきなど題材に幅を持たせる
7. 「仕組み化が大事」「社長の仕事を減らそう」などの安易な結論に着地させない
8. 毎回サービス紹介や固定ポストへの誘導を入れない
9. 本文に【要確認】などの穴を残さない。確認済みの事実だけで完成させ、実例が無ければ考え方・方針として書く。確かめたいことは本文とは別に質問する
10. 言い切りの基準：確認済みの経験・実績、自分で考えてきたこと・自分の方針は、はっきり書いてよい。他人の気持ち・一般論・未確認の成果は断定しない。
    （本人は強い文章が嫌なのではなく、根拠がないことを言い切るのが苦手）

## 1. 入力部分：どんな情報を入れて投稿を作るのか

| 材料 | 中身 | 使い方 | 使わないこと |
|---|---|---|---|
| **直近7日の返信・引用ポスト**（いちばんの材料） | Xアナリティクスの CSV から、本人が書いた60字以上の返信と引用（推定）を取り込んだもの。1件ずつ R1, R2… と番号を振る | 本人が実際に関心を持ったこと・考えたこと・新しく出てきた疑問を拾う | 相手の元投稿はデータに無いので、何についての発言かを推測で確定しない |
| **今週あったこと** | 生成のときに本人が1行ずつ入れるメモ。M1, M2… と番号を振る | 返信と同じく材料として使う | — |
| **事業の方向性・ターゲット** | 発信設計のシート（目的・ターゲット層・独自性など） | 誰に向けた発信か、軸から外れていないかの確認だけ | ここから毎回テーマを作らない。書かれている事業の多くは「これからやりたいこと」なので実績として書かない |
| **外部ライターの企画シート・型カタログ** | 以前のライターの企画と、完成投稿から取り出した「構成の型」（骨組み・冒頭・締め） | テーマの選び方・切り口の作り方だけを参考にする | 内容の言い換え・再利用はしない。出来事・数字・セリフは使わない |
| **文体ルール**（区分＝文体） | ライターの雛形と本人の書き直しの差分から取り出した、本人の書き方（語尾・改行・言葉遣い・禁止表現など） | 文体はここだけで再現する | — |
| **発信の軸・価値観**（区分＝軸・価値観） | 本人が大切にしている考え方（例：「社長語を、現場語に」）。本人が書く | 企画の方向性の判断に使う | 毎回この結論に着地させない |
| **過去の主張・エピソード**（区分＝過去の主張） | 文体ルールと一緒に抽出された「繰り返している主張」「よく書くテーマ」「雛形にあったテーマ」 | 焼き直し防止（同じ結論に着地しない） | 書き方の手本としては使わない |
| **系統の傾向**（過去半年の数字） | 過去の投稿を「役割」「分類」に振り分けて、インプレッションの中央値と、1本あたりの返信・フォロー・プロフィールアクセスを比べたもの | どの系統が読まれ、どの系統がつながりにつながったかの参考 | 過去の投稿の **本文** は渡さない（中身まで引っぱられて焼き直しになるため） |
| **週の傾向**（本人が毎週決める） | 曜日ごとの長さ（長文/短文）と分類（紫微斗数の8分類：拡散・共感・人脈・助け・成果・専門・自分の言葉・仕組み化） | 各枠の長さと分類を決める | — |
| **採用した企画案** | 過去の返信から発掘した企画のうち、本人が採用したもの | 企画の候補 | — |
| **反応ログ** | 読者からのコメント・引用した相手の投稿など | 他人の視点として使う。借りるのは論点だけ | 他人の言い回し・構成・事例は使わない。1人の発言を一般化しない |
| **禁止する着地／使用禁止のエピソード** | 設定シートに本人が書く（例：「抱え込まない」「仕組み化すれば」／何度も使った昔の話） | この結論・この話は使わない | — |

**既定で渡さないもの**：過去の投稿の本文、経歴・年表、古い一次情報（設定で戻せる）

## 2. 生成ロジック：どうやって切り口や構成を決めているのか

流れは **企画 → 執筆 → 編集** です。

> 2026-10 時点の既定は「企画の方式＝材料に合わせる」です。手順1の機械的な割り当てはせず、
> 手順2の企画会議が材料を見て、1本ずつ芯（主張・場面・問い・感情・観察）・芯になる一文・読者に残るもの・読後感・締め方を決め、
> 型・角度・役割は合うときだけ選びます。以下の手順1は「先行割り当て」（以前の方式）の説明です。

### 手順1：枠ごとの割り当て（機械的に決める）

7つの枠それぞれに、次を先に決めます。

| 項目 | 決め方 |
|---|---|
| 長さ・分類 | 本人の「週の傾向」シートどおり |
| 役割（目安） | 既定の配分：実際に取り組んだ仕事2／経営者が見落としやすい問題2／失敗や試行錯誤1／社長と現場のすれ違い1／人柄や日常の気づき1。同じ役割が続かないように並べる。材料に合わなければ変えてよい |
| 構成の型 | 型カタログから順に割り当て、他の枠と被らないようにする |
| 視点の角度 | 8種類（「前はこう思っていたが違った」「よく言われることの逆」「失敗から」「数字の裏側」など）を順に割り当てる |
| 冒頭のカギカッコ | 週2本まで（2本目と5本目だけ許可）。しかも材料にある言葉のときだけ |

### 手順2：企画（AI・1回）

書く前に、7本ぶんの企画を1回でまとめて決めます。
枠ごとに「使う材料（R/M番号）」「題材」「主張（1文）」を割り当てます。

- 同じ主張・同じ材料・同じ出来事の返信は1本にまとめる（例：同じ人物の話をした返信が2件あれば、1本の材料にする）
- 材料が足りない枠は、材料を空にして題材を割り当てる（これからやりたい仕事 → 仕事の考え方 → 実務の視点 → 人柄 → 日常の気づき の順。これからやりたい仕事は週1本）
- 同じ材料が2つの枠に入っていたら、プログラム側で後ろの枠から外す

### 手順3：執筆（AI・2本ずつ並列）

GASの6分制限があるので、2本ずつ4回に分けて同時に書きます。
1回ぶんの依頼には次が入ります。

- 材料一式（上の表）
- その回の枠の割り当て（長さ・分類・役割・型・角度・カギカッコ可否）
- その回の企画（材料・主張・題材）
- **同じ週の他の本の主張と材料**（「これを言わない・使わない」として）
- すでに書いたテーマ（同じ結論に着地しない）
- 本人のルール（0章）

途中で出力が切れた場合は、読めた投稿だけを残し、欠けた枠だけを1本ずつ作り直します。

### 手順4：編集（AI・1回）

7本を並べて、テーマ・主張・エピソード・読後感の4つで重なりを確認します。

- 重なったグループからは最も良い1本だけを残す（同じくらいなら、穴が無いほう・材料に忠実なほう）
- 業務改善・仕組み化が3本以上なら「題材の偏り」として扱う
- 実績が無いことを実績のように書いている箇所、材料に無い発言を書いている箇所を「言い過ぎ」として挙げる（本文は直さず、別欄に書く）
- 外した枠には、まだ使っていない返信を割り当てる。無ければ題材を割り当てる

### 手順5：作り直しと再確認（AI）

外した枠を、割り当てた材料1つ（または題材）だけで作り直します。残す本の一覧と、外した案を渡して同じ方向に戻らないようにします。
作り直した分がまだ重なっていれば、題材を変えてもう1回だけ作り直します。

時間が足りないときは作り直さず、重なった本を消さずに「作り直し未実施」と印を付けます。

### 本人が選び直すとき

メニューから「残す本の番号」（例：1,2,4）を入れると、残りの枠だけを手順4〜5で作り直します。

## 3. 出力部分：どんな投稿案が出てくるのか

### 投稿案シート（1行1投稿）

| 列 | 中身 |
|---|---|
| 枠 | 1〜7 |
| 分類・役割・使った型・ターゲット層・テーマ | 割り当てと結果 |
| 投稿の狙い | 30字以内 |
| 元になった返信・切り口 | どの返信（R番号）か、どの題材か |
| 本文 | X投稿文の叩き台 |
| 冒頭3行 | 一覧で比べる用 |
| 事実確認が必要な箇所 | 本人への質問。「言い過ぎの可能性」もここに書く。本文は答えが無くても成り立つように書く |
| 編集メモ | 「1・6・7本目の重なりから残した1本」「R3から作り直し」「材料なし：題材『人柄』で作った叩き台」など |
| 自己チェック | 機械チェックの結果（4章） |
| 状態 | 未／質問あり（本文は完成、質問だけ別欄）／要確認（本文に穴が残った＝ルール違反）／残す／空き |

### 週形式シート

本人がふだん使っている「1週間ブロック」の形（A列にラベル、B〜H列に月〜日）で書き出します。
見出しに「（質問あり）」「（要確認・未完成）」が付きます。そのまま予約用にコピーします。

## 4. 評価・改善部分：生成した投稿の質をどう判断しているのか

### 4-1. 機械チェック（AIを使わない・毎回自動）

| チェック | 判定 |
|---|---|
| 禁止語 | 文体ルールの禁止語（本人が過去に自分で消した語）が入っていないか |
| 出どころ未確認の数字 | 「数字＋単位（年・歳・件・人・回・分・円・%など）」が、一次情報に無い数字なら印 |
| 禁止した着地 | 「抱え込まない」「仕組み化すれば」などが入っていないか |
| 使用禁止のエピソード | 何度も使った昔の話が入っていないか |
| 誘導 | 「固定ポスト」「DM」「ご相談ください」などの投稿が週2本以上なら印 |
| 本文の穴 | 【要確認】が本文に残っていないか |
| 冒頭カギカッコ | 週3本以上なら警告 |
| 「仕組み」で締める投稿 | 週3本以上なら警告 |

問題のある行は赤くなり、本人は赤い行だけを見ればよい作りです。

### 4-2. AIによる確認

- 編集（2章 手順4）：重なり・題材の偏り・言い過ぎ
- 再確認（手順5）：作り直した分がまだ重なっていないか・言い過ぎが無いか

### 4-3. 本人による確認

- 「状態」が「質問あり」の行の質問に答える
- 気に入らない本があれば、残す本の番号を入れて残りを作り直す
- 週形式の「修正欄」に直した文を書く

### 4-4. 改善のループ

| 仕組み | 何が良くなるか |
|---|---|
| 文体の抽出 | 雛形（AIやライターの文）と本人の書き直しの差分から、本人の書き方のルールを取り出す。修正欄に書き直しが溜まるほど、文体ルールが更新される |
| 系統の分析（毎週CSVを貼る） | 役割・分類ごとに、読まれやすさ（インプの中央値）と、つながりやすさ（1本あたりの返信・フォロー・プロフィールアクセス）を比べる。平均ではなく中央値にしているのは、外部の互助グループで一時的に伸びた回に引っぱられないため |
| 企画の発掘 | 過去の返信から新しい企画を掘り出し、A/B/Cで判定する。A判定は「過去の投稿と結論が違う」ときだけ。本人が採用した企画は次の生成で使う |
| 反応ログ | 読者からのコメントや引用した相手の投稿を貯め、他人の視点として使う |
| 設定 | 禁止する着地・使用禁止のエピソード・役割の配分・材料が無い枠の扱いを、本人がシートで直せる |

## 5. 分かっている弱点

1. **評価の多くを、同じAIが自分でしている。** 機械チェック以外の「重なり」「言い過ぎ」の判定は、書いたのと同じモデルが行っている。人が採点した正解データは無い
2. **生成した企画と、実際の反応が直接つながっていない。** どの企画（役割・題材・型）で書いた投稿が伸びたかは記録しておらず、系統の分析はCSVの本文から振り分け直している
3. **CSVの本文は約150字で切れている。** 系統の振り分けは冒頭だけで判断している
4. **引用ポストはCSVで区別できない。** 「末尾がリンクで終わる自分の投稿」を引用とみなしている（推定）
5. **60字未満の返信は材料にしていない。** 相槌を除くためだが、短くて鋭い返信も落ちている可能性がある
6. **材料の量が本人の返信の量に左右される。** 返信が少ない週は、材料が無い枠が増え、考え方・方針の投稿が多くなる
7. **GASの6分制限。** 生成が長引くと、編集や作り直しを省くことがある（そのときは報告して、本人が作り直しを押す）
8. **文体ルールは、書き直しの差分が溜まらないと更新されない。** 叩き台をそのまま出し続けると、文体ルールは止まったままになる

## 6. このAIにお願いしたいこと

（ここは毎回書き換えて使ってください。例を3つ置いておきます）

- **例A：仕組みの見直し**
  この設計を読んで、入力・生成・出力・評価のどこに一番の弱点があるか、優先度の高い順に3つ挙げてください。それぞれ、スプレッドシートとGASの範囲で実現できる改善案をつけてください。

- **例B：評価の改善**
  4章の評価は「AIが自分で判定している」部分が大きいです。本人の手間をほとんど増やさずに、投稿の質をもっと客観的に測る方法を提案してください。

- **例C：今週の投稿案の確認**
  下に今週の7本を貼ります。0章のルール（特に1・3・4・6）に違反している箇所を、本文の該当部分を引用して挙げてください。直した文は書かず、違反の指摘だけをしてください。
