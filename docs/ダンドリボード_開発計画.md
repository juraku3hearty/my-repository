# ダンドリ — 開発計画 v1

**名称：ダンドリ**（段取り＋鳥。段取りを仕切る、よく喋る鳥のキャラクター名でもある）

家族の予定共有カレンダーではなく、家を回すための「段取りボード」。
コンセプト：**詳細は自分だけ、段取りは家族だけ。**

元仕様：Manus AI作成の依頼文（家族の段取りボード）をベースに、MAYUの技術資産・実運用に合わせて再設計。

## 設計原則（最重要）

> **家族は入力しない。返事するだけ。**

家族アプリが死ぬ理由の9割は「入力してくれない家族」。ダンドリは家族にアプリを開かせない。
いつものLINEにダンドリの方から聞きに来て（「今日の夕飯、いる？いらん？」）、ボタン1タップで義務完了。
自分から登録する人は家庭に1人いればよく、他の家族は「返事する人」。
鬼上司Bot・ハヨヤレで実証済みの「向こうから来るから続く」原理の家庭版。
成功指標は「旦那さんが毎日ボタンを押し続けるか」。

> **デフォルト＋例外方式：平和な日は、鳥は黙る。**

毎日全員に「夕飯いる？」と聞くのは間違い（基本家で食べる人、毎日聞かれるのが嫌な年頃もいる——MAYU指摘）。
各メンバーが基本設定を持ち（夕飯は基本いる／帰宅目安18時 等）、ダンドリが扱うのは**例外と未確定だけ**。
「今日いらん」は本人がボタンで一言申告。不規則な人だけ「毎朝聞いて」設定を選べる。
年頃の子は「聞かれたくない」設定OK（申告した時だけボードに載る＝干渉ゼロ）。
ダンドリが喋るのは「迎えが未定」「明日は遠足で弁当」など確認が必要な時だけ。
副産物としてPush数が激減し、LINE費用もさらに下がる。

> **リマインドは、お母さんに集めない。担当者本人に直接届ける。**

家族アプリの最大の罠は「全通知が母に集まり、母がリマインド中継局になる」こと（MAYU指摘）。
・リマインドは担当者本人へ（ジャージ→長男、迎え担当→父。母を経由しない）
・担当未定のものだけ全員へ「誰か行ける？」→ 最初に【引き受ける】を押した人で確定
・本人事項（夕飯いらん・帰宅時間）の督促は本人へ。「聞いといて」を母に振らない
・母に届くのは「母が担当のもの」と「家族全体で未決のもの」だけ
ダンドリの存在意義＝母が「家族の予定を全部覚えてる係」から降りられること。通知設計がこれを裏切らない。

**メンバーの3タイプ（全員がLINEを受ける必要はない）：**
1. LINE接続メンバー（友だち追加済み）… 自分宛のことだけ届く
2. プロフィールのみ（LINE未接続の子ども等）… 通知なし。その子宛のリマインドは担当の親へルーティング
3. 通知オフ（年頃の子等）… 話しかけない。本人が開いた時だけ応答
全員一斉に飛ぶのは「担当未定の募集」だけで、最初に引き受けた人が出たら終了。

**家族の紐付け＆二層通知（グループ招待方式）：** ダンドリ（Bot）を家族のLINEグループに招待する。

・**家族グループ層（全員向け）**：募集「17時の迎え、誰か行ける？【行ける】」／全体連絡「明日は遠足、弁当やで」／金曜の棚卸し。
　全員が同じ画面で見て最初にタップした人で確定。
　**✅ 実測済み（MAYU）：グループ送信は人数分カウント**（10人グループ＝10通）。コストメリットは無いので、
　グループで喋るのは価値が高い場面だけに絞る（募集・全員連絡）。日常リマインドは担当者個人へ1:1。
　規模拡大時のレバー：グループまとめ便（1日1回に集約）／重要度低いものはボード掲載のみ（開けば見える＝無料）。
　グループ内replyの無料カウントは平井家パイロットで実測確認する。
　流れるのは「家族に見せる段取り情報」だけなのでプライバシー設計とも整合
・**1対1トーク層（個人向け）**：自分の担当リマインド、個人予定の登録、プライベートな確認。他の家族には見えない
・**紐付けフロー**：母がダンドリを家族グループに招待 → ダンドリが「みんな、自分の名前タップしてや」
　→ 各自1タップで紐付け完了（グループにいる＝家族の証明なので、なりすまし対策も実質不要）
・友だち追加していない家族にもグループ経由で全体連絡は届く（個人リマインドが欲しくなったら友だち追加）
・グループを持たない家庭向けの予備として招待リンク（QR/URL）方式も残す

## 判断済みの方針

| 論点 | 決定 | 理由 |
|---|---|---|
| 規模 | **ガチ版（Webアプリ）でいく** | GAS/LINEだけでは家族ボードUIと権限分離が成立しない。MAYU了承済み |
| 技術スタック | **Next.js + Supabase + Vercel** | メルノキ・整骨院システムと同じ＝資産流用・運用ノウハウあり |
| 子どもの利用 | **LINE LIFF**（アカウント不要でLINEから開く） | 子どもに新規アカウントを作らせない。家族LINEは既に存在する。メルノキでLIFF実装実績あり |
| 通知 | **LINE**（家族グループ or 個別） | 日本の家庭の現実解。アプリPush（PWA）は後続 |
| 通知キャラ | **よく喋る鳥「ダンドリ」で確定** | 名前＝アプリ名＝キャラ。家中の伝言を運ぶ世話焼きな鳥は子どもにも刺さり、仕事シリーズ（おばちゃん・鬼頭課長）とブランドを分けられる。「明日体育やで！ジャージ！ジャージ！」と繰り返す芸が鳥と相性抜群 |
| Googleカレンダー連携 | **初期版から除外** | OAuth審査と抽象化実装が重い。v2で「可用性のみ参照」を検討。当面は「用事あり」を手入力 |
| 配布アーキテクチャ | **中央集権型：「ダンドリ」公式アカウント1個に全家庭が友だち追加** | 対象は普通の家庭＝LINEチャネル自作は不可能（MAYU指摘）。利用者の作業はQRで友だち追加のみ、セットアップという概念を消す。鬼上司/ハヨヤレと逆の設計だが、月額課金商品なので通知コストを売上で払える |
| LINE費用（実測ベース） | グループ送信は人数分カウント（MAYU実測）。有料家庭＝個人リマインド40〜60通＋グループ発言10回×4人≒**月100通前後＝100〜150円/家庭**（売上500円の2〜3割）。500家庭規模ではスタンダード超過分が効くため、まとめ便・ボード掲載格下げのレバーで通数を制御する。無料版はPushしない（reply＝無料のみ）。「鳥が自分からさえずるのは有料」がフリーミアムの柵 | |

## 💬 会話クエリ（無料版の主役機能）

「今日の予定は？」「明日って弁当いる？」「今週の送迎は？」と**LINEで聞けば、その家族のボードを組み立てて返す**。
動的な内容でもLINE課金上はreply＝無料・無制限（子ども食堂Botの「次いつ？」と同じ仕組みの発展形。MAYU発案）。
Geminiを挟むので聞き方は自由な日本語でOK。
→ 無料版は「聞けば何でも答える家族秘書」。有料版との差は「聞かなくても向こうから来るか」だけ、という綺麗な柵になる。

**グループ内クエリも成立する（グループ発言へのreply＝無料）。** 設計要件：
①「ダンドリ」宛と判定した時だけ応答（家族の雑談には反応しない）
②集計回答に対応（例「来週外食できそうな日は？」＝全員の夕飯デフォルト＋例外から空き日を計算）
③会話クエリでもプライバシー分離を厳守（非公開詳細は誰に聞かれても抽象情報までしか答えない）


## 🌟 キラー機能：行事カレンダーOCR自動入力（MAYU追加要件）

学校・園の月間プリント／年間行事表を**写真に撮って投げるだけ**で、段取りボードに自動入力する。

```
プリントを撮影 → LINEでダンドリに送る
  → Gemini Vision が日付・行事・持ち物を構造化抽出
     例）10/3 体育参観 → ジャージ洗濯（前日）、10/15 遠足 → 弁当・水筒
  → 段取りボードに「準備タスク」として自動登録（前日夜・当日朝にリマインド）
  → 誤読は「直して」で修正（ハヨヤレと同じ操作感）
```

- 技術実証済み：タイムカードOCR（No.2案件）と同じ Gemini Vision パターン
- 行事名から準備物を推論するのはAIの得意分野（体育→ジャージ、遠足→弁当・レジャーシート）
- **競合の共有カレンダーに存在しない差別化機能**。「プリント地獄からの解放」は保護者に一番刺さる訴求

## MVP機能（フェーズ1）

1. 親アカウント作成・家族グループ作成・子どものアカウント不要プロフィール（LIFF）
   - **初期設定ウィザード（必須）**：メンバー登録時に各自の「平常運転」を最初に入力させる
     ・夕飯：基本いる／いらん（**必ず先に決めさせる**。これが決まってないと毎日聞くハメになる）
     ・帰宅目安・弁当の要否も同様にデフォルト登録
     ・**曜日別に設定可能**（例：火曜は塾で夕飯遅い、水曜は部活で弁当いる）
     ・以降ダンドリは「デフォルトとの差分」だけを扱う（設計原則2の土台）
2. 「今日・明日・今週」の段取りボード（月間カレンダーは作らない）
   - カード：今日の夕飯（いる/いらん/未回答）／明日の準備／送迎の調整／帰宅の見通し／家族の都合
   - 未回答・未定・期限超過を最優先表示
3. 定型入力：「明日弁当いる」「金曜ジャージ洗っといて」「今日は夕飯いらん」→ ボタン＋短文
4. **個人予定表**：各自が自分の予定を普通に登録できる（タイトル・場所・メモ＝本人だけに見える）。
   登録時に家族への見せ方をワンタップ選択（外出／帰宅目安／送迎要否／夕飯への影響）
   → 1回の入力で「自分の予定表」と「家族ボードへの段取り共有」が同時に完了する（二度書き不要）
5. プライバシー分離：家族に見えるのは「予定あり／外出／帰宅目安／送迎要否」のみ。詳細は本人だけ
6. **行事カレンダーOCR自動入力**（キラー機能。フェーズ1に含める）
7. ダンドリ通知（LINE）：未回答の夕飯・未定の送迎・明日の準備を、1日2回のダイジェストで
8. 状態変更：完了／引き受け／不要／あとで

## Manus設計レビューの記録（2026-09-05）

Manusが公式資料で裏取り→MAYU実測と全一致（Push=人数分／Reply=ノーカウント）。追加で採用した実装方針：
- 送信ジョブは実行前に当月使用量・家庭別予算を確認し、超過しそうなら低優先度をボード表示に格下げ
- グループのライフサイクル処理（Bot参加→家族候補作成／離脱・解散→紐付け無効化）
- 会場など詳細情報は「送迎を依頼した時だけ担当者に渡す」need-to-know開示
- ⚠️ 修正指示済み：グループメンバーID一覧APIは認証済みアカウント限定の可能性が高い。
  紐付けの主方式は「グループ内postback（groupId＋userId）による在籍証明」とする

## スプリント記録

### スプリント1 ✅ 完了（2026-09-05）

段取りボードの画面がダミーデータで動くところまで。コードは **このリポジトリの `dandori-app/`**
（`dandori-app` リポジトリがまだ無かったため。中身は独立した Next.js プロジェクトなので、
リポジトリを作ったらフォルダごと移すだけで動く）。

- Next.js 16 + TypeScript、UIライブラリなしの手書きCSS（モバイル1カラム）
- 今日 / 明日 / 今週 の3タブ。月間カレンダーUIは作っていない（方針どおり）
- 「まず、これ」＝**期限超過・担当未定・未回答**を最上部に固定表示。3つとも無い日は鳥が黙る
- 夕飯カードは**曜日デフォルト＋その日の例外**から人数を自動計算。未回答は赤＋いる/いらんボタン
- タスクは担当者アバター付き。担当未定は【引き受ける】、自分の担当は【やった】
- 他人のプライベート予定は「外出（帰り23時ごろ）」に自動で置き換わる
- 画面下の「いま見てる人」でメンバーを切り替えると見え方が変わる（開発用スイッチ）
- `?tab=week` `?as=m_sota` のクエリで初期表示を指定できる（動作確認用）
- `supabase/schema.sql` にテーブル定義（families / members / line_links / weekday_defaults /
  day_overrides / events / tasks / ocr_uploads / notifications）

**設計上の判断メモ**

- `lib/board.ts` は React に依存させない純関数にした。通知エンジン（スプリント4）が
  「何を誰にいつ送るか」を決めるときに同じ関数を使うため
- 日付境界はすべて `lib/date.ts` の Asia/Tokyo 基準を通す。Vercel のサーバーは UTC なので、
  素の `new Date()` で日付を出すと深夜〜朝9時に「今日」が1日ずれる
- **プライバシー分離はサーバー側で落とさないと成立しない。** 画面で隠すだけだと
  ページのソース（RSCペイロード）に本文が残る。`maskSnapshotFor()` を用意してあるので、
  LIFFログインで閲覧者が確定するスプリント2で `app/page.tsx` に差し込む
- 「今週」は暦の週ではなく**今日から8日**。金曜や土曜に開いたとき1〜2日しか出ないと
  段取りボードとして役に立たないため
