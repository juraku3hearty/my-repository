判断できる状態にするための進行表。

## 結論

**募集ページは完成済み（1日目の時点で出せる）。**
**正式募集（実際にお金を受け取る）が7日で開けるかは、外部作業3件に依存する。**

そのため、`JOIN_OPEN` という切り替えを入れた。7日目にどちらの状態でも出せる。

| JOIN_OPEN | 募集ページのCTA | /join | 用途 |
|---|---|---|---|
| `1` | 月額9,800円（税込）で申し込む | 決済へ進む | 正式募集 |
| `0` | 受付開始のご案内を受け取る | /prelaunch へ転送 | 事前案内 |

`0` のとき、メールアドレスだけを `prelaunch` に預かる。会員にはしない。
受付を開いたら `/admin/prelaunch` からCSVで取り出して案内を送る。

## 7日目に `JOIN_OPEN=1` にできる条件

すべて揃ったときだけ `1` にする。1つでも欠けたら `0` のまま出す。

- [ ] 独自ドメインでHTTPS配信できている（E2）
- [ ] 本番のsecretsが環境変数で入っている（A24）
- [ ] ROBOT PAYMENT のキックバックURLが登録され、`acid`/`em`/`cod` が返ってくる
- [ ] テスト決済で 申込→決済成功→ログインメール受信→Q&A利用 が通った
- [ ] テスト決済で 決済失敗→利用停止、解約→遮断 が通った
- [ ] ログインメールが実際に届く（SMTP）
- [ ] 院長がナレッジを承認済み（F2）。承認0件で公開すると検索結果が空になる
- [ ] 募集ページの「専門家への確認」の表現が確定している（legal-todo.md の★）

### コメントで集めた質問をQ&Aにするとき

プライバシーポリシーは「メールアドレスのみを取得します」と書いている。
SNSのコメントは当社が取得する個人情報ではないが、**本文をそのまま転載すると
投稿者が特定される**。次を必ず通す。

1. 患者の情報を落とす（年齢・部位・経過・地域・時期）
2. 投稿者が分からない形に書き直す（「ある先生から」も使わない。質問だけ残す）
3. 院長が確認してから承認する
4. 原文は保存しない
