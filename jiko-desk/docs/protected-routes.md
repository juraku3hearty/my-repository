## 0. 検証環境の封じ込め（ご指示1）

認証が未実装のまま外部に出ないよう、コードの側で止めるようにした。

| 対策 | 実装 |
|---|---|
| `APP_ENV` が `dev` 以外なら起動しない | `raise SystemExit("この雛形は検証専用です…")` |
| 待ち受けを `127.0.0.1` に固定 | `app.run(host="127.0.0.1", …)`。外部から到達できない |
| **ダミーデータ以外を開かない** | `APP_DB_PATH` が `demo.sqlite3` でなければ起動時に落とす |
| 実データを持ち込まない | 実データは `jiko.sqlite3`。この雛形からは開けない |

```python
APP_ENV = os.environ.get("APP_ENV", "dev")
if APP_ENV != "dev":
    raise SystemExit("この雛形は検証専用です。認証（require_member）が未実装のため本番では起動できません。")
...
if DB_PATH.name != "demo.sqlite3":
    raise SystemExit("検証環境ではダミーデータ（demo.sqlite3）以外を開けません。")
```

**公開してよいのは `require_member()` の中身が実装され、2章の全経路が埋まってからである。**

## 2. 動画の直接アクセス（ご指示4）── アプリだけでは守れない

### アプリ側で確認できたこと

| 確認 | 結果 |
|---|---|
| 許可外の動画はボタンが出ない | 「健康保険の併用」（`video_visible=0`）→ ボタン0件 |
| HTMLソースにURLが出ない | `vimeo.com` の文字列・`video_id` とも **0件** |
| 許可外のIDを直接POST | `KB-DEMO-007` → トップへ戻る（飛ばさない） |
| 非公開ナレッジのIDを直接POST | `KB-DEMO-009` → トップへ戻る |
| 再承認待ちのIDを直接POST | `KB-DEMO-008` → トップへ戻る |
| 許可済みのIDを直接POST | `KB-DEMO-002` → `vimeo.com/…` へ遷移 |

### しかし、これだけでは不十分

**URLを隠すことは、アクセスを防ぐことではない。** 現状のVimeo動画が「リンクを知っている人なら見られる」設定なら、
過去にURLを知った人や、URLを推測した人は、こちらのアプリを経由せずに見られる。

**【要確認・MAYUさんの作業】** Vimeo側で次のいずれかを設定する必要がある。

| 方法 | 内容 | 向き不向き |
|---|---|---|
| **ドメイン制限（推奨）** | 指定したドメインの埋め込みページからのみ再生可。Vimeoで直接開いても再生されない | ◎ 会員サイトに埋め込む形にすれば自然 |
| パスワード保護 | 動画ごとにパスワード | △ 共有されたら終わり |
| 非公開（自分だけ） | 会員も見られない | ✕ |

**推奨：会員に見せる動画はドメイン制限をかけ、会員サイト内に埋め込んで再生する。**
`vimeo.com` へ飛ばす今の作りは、ドメイン制限と両立しない。**動画の見せ方そのものを埋め込みに変える必要がある。**
これは設計変更なので、連携方式の確定とあわせて判断したい。

`lessons` テーブルの `member_visible` は **既定0**。入れ忘れた動画が会員に出ることはない。

## 4. 承認は「版」で持つ（ご指示3）

確認者名と確認日が入っているだけでは判定しないようにした。

### データの持ち方

| 列 | 内容 |
|---|---|
| `answer_version` | 回答本文のSHA-256（先頭16桁）。**本文が1文字変われば変わる** |
| `approved_version` | 院長が承認した時点の本文のハッシュ |
| `approval_state` | `承認済` / `再承認待ち` / `未承認` |

### 表示と公開の条件

```sql
-- 会員の検索対象に入る条件
publish_status = '公開可'
AND approval_state = '承認済'
AND approved_version = answer_version   -- 承認した版と今の本文が一致
AND approved_version <> ''
```

**本文を修正すると `answer_version` が変わり、`approved_version` と食い違う。
その瞬間に会員の検索結果から消え、再承認するまで戻らない。**

### 検証結果

`KB-DEMO-008`（施術証明書のQ&A）の本文を書き換え、再承認していない状態を作った。

```
KB-DEMO-008  approval_state=再承認待ち  版一致=0  publish_status=公開可
→ 「施術証明書の書き方」で検索：主回答なし。相談導線のみ
→ 直接 /video-click にPOST：飛ばさない
```

**`publish_status` が「公開可」のままでも、版が一致しないので会員には出ない。**
公開フラグの消し忘れでは漏れない作りになっている。

### 画面の表示

| 状態 | 表示 |
|---|---|
| 承認済＋版一致 | 🟢 **院長確認済み**　院長 平井／確認日 2026-09-22 |
| 再承認待ち | 🔴 **再承認待ち**　回答が修正されたため、承認をやり直しています |
| 未承認 | 🔴 **確認前**　院内の確認がまだ済んでいません |

通常は会員の検索結果に出ないため、この表示は**公開判定を誤って通したときの最後の砦**である。
