# 保存する情報と、その扱い

2026-10-12 / 試作時点。**本番公開前に院長と合意すること**

## 1. 保存する情報（これだけ）

### 会員（`members`）

| 列 | 内容 | なぜ要るか |
|---|---|---|
| `member_id` | 自前発番（`JK-000123`） | 決済の `cod` に入れる識別子 |
| `email` / `email_norm` | メールアドレス | ログインリンクの送付と照合 |
| `robotpay_acid` | 自動課金番号 | 決済側との結び目 |
| `status` / `paid_through` / `grace_until` | 利用資格 | 利用可否の判定 |
| `last_payment_at` / `last_failure_at` | 日時 | 督促の判断 |
| `created_at` / `updated_at` / `cancelled_at` | 日時 | 履歴 |

### 保存しないもの（意図的に）

| | なぜ |
|---|---|
| **カード番号・有効期限・名義・ブランド** | 決済代行の画面で入力され、こちらを通らない。保持すれば保護義務と漏洩時の被害が跳ね上がる |
| **氏名・住所・電話番号・生年月日** | 運用に使わない。キックバックの追加申請もしない（`em` と `nm` のみ依頼、`nm` も使わなければ依頼しない） |
| 配送先情報 | 物を送らない |

> **原則：使う予定のない個人情報は、無料でも受け取らない。**

### 利用ログ（`search_log` ほか）

質問文は**記録前にマスキング**する（`applog.py`）。電話番号・メール・住所・氏名らしき語・番号を置換。
会員IDは**ソルト付きハッシュのみ**を保存し、生のIDを残さない。

### ログイントークン（`login_tokens`）

**生のトークンは保存しない。** SHA-256のハッシュのみ。
使用済み・期限切れは `purge_tokens()` で削除する。

### 決済通知（`payment_events`）

受け取った内容をそのまま保存する。**カード情報は含まれない**（仕様上、下4桁すら既定では来ない）。

## 4. 保存期間と削除

| 対象 | 期間 | 削除方法 |
|---|---|---|
| 利用ログ（検索・閲覧・評価） | **13か月** | 日次バッチで自動削除。**未実装** |
| ログイントークン | 15分（使用済みは即時） | `purge_tokens()` |
| 決済通知の生ログ | **24か月**（照合と問い合わせ対応のため） | 未実装 |
| 退会会員の情報 | **退会から13か月**。その後メールアドレスを削除し、統計用に `member_id` と期間だけ残す | 未実装 |

**退会者からの削除依頼への対応**
1. 本人確認（登録メールアドレスからの依頼であること）
2. `members` のメールアドレスを消し、`status='deleted'` にする
3. 利用ログは既にハッシュ化されているので、個人の特定ができない状態で残る
4. **決済記録は決済代行側にあり、こちらでは消せない**（税務・会計上も残す必要がある）

→ **会員規約に「決済記録は決済代行会社に残る」と明記する。**
