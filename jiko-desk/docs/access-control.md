# 未承認ユーザーに情報を返さないための設計

2026-10-12 / **設計の整理。認証の本実装は連携方式の確定後**

ご指示8「非ログイン、退会後、URL直接アクセス、API直接呼び出しのいずれでも、
未承認ユーザーに情報を返さない」への対応。

## 原則：判定を1か所に集める

経路ごとに判定を書くと、必ずどこかが抜ける。**すべての経路が同じ関数を通る**ようにする。

```python
def require_member():
    """会員向けの全経路が通る関所。ここだけを正とする。"""
```

判定の根拠は **`members.status` と `members.paid_through` だけ**。
Cyfons側のログイン状態は根拠にしない（Cyfonsを止められない場合があるため、
Cyfonsに入れる＝Q&Aを使える、にすると退会者が通ってしまう）。

## 経路ごとの挙動

| 経路 | 挙動 | 実装 |
|---|---|---|
| 非ログイン | ログイン画面へ。検索結果は一切返さない | `require_member()` が False |
| 退会・停止後 | 支払い／退会の案内へ。**ログインはできるが検索結果を返さない** | `status != 'active'` |
| URL直接アクセス（`/?q=...`） | 同じ関所を通るので素通りできない | 全ルートに適用 |
| API直接呼び出し（`/api/*`） | HTMLではなくJSONで `401`。本文に中身を含めない | 同じ関所＋JSON応答 |
| セッション窃取 | 署名付きリンクのトークンは60秒・1回限り（nonce）。使い回せない | トークン検証 |
| 検索語なしでのアクセス | 何も返さない（一覧表示をそもそも作らない） | 実装済み |

## すでに実装した防御（雛形で確認済み）

| | 内容 | 確認方法と結果 |
|---|---|---|
| 1 | 会員の検索対象は `publish_status = '公開可'` のみ | 「後遺障害 等級」→ 0件。非公開ナレッジは出ない |
| 2 | ナレッジの一覧表示・一括取得の画面を作らない | 検索語が空のときカード0件 |
| 3 | **動画URLをクライアントから受け取らない** | `/video-click` は `item_id` のみ受け取り、サーバーがDBを引く |
| 4 | **公開許可のない動画はURLをHTMLに出力しない** | 「健康保険の併用」の結果に `vimeo.com` の文字列が一切出ない |

## 確認状況の表示（ご指示4）

**確認を受けていないものに「確認済み」と出さない。** 表示の根拠を実績の列に置いた。

| DBの状態 | 画面の表示 |
|---|---|
| `internal_status = '院内確認済'` かつ `internal_reviewed_at` あり | 🟢 **院長確認済み**　院長 平井／確認日 2026-09-22 |
| 上記以外 | 🔴 **確認前**　院内の確認がまだ済んでいません |
| `expert_status = '確認済'` | 🟢 専門家確認済み |
| `outdated = 1` | 🔴 制度変更の可能性あり |

バッジは `internal_status` の文字列ではなく、**確認者名と確認日が両方そろっている**ことを条件にした。
片方でも空なら「確認前」になるので、データの入れ忘れが「確認済み」に化けない。

なお、会員の検索結果に出るのは `publish_status = '公開可'` のものだけなので、
通常は「確認前」は表示されない。この表示は**公開判定を誤って通したときの最後の砦**である。

## ナレッジと書式の分離（ご指示7）

| | 書式ダウンロード | Q&Aの内部ナレッジ |
|---|---|---|
| 中身 | 白紙のひな形（施術証明書・同意書） | 講座から作った回答本文 |
| 置き場所 | 静的ファイル。会員サイト側 | DB。Q&Aアプリ側 |
| 一括取得 | 可（ひな形なので問題ない） | **提供しない** |
| 画面 | メニューから別導線 | 検索した結果だけ、1件ずつ |

トップページに「書式ダウンロードは白紙のひな形のみです。Q&Aの回答本文をまとめて取得する機能はありません」と明記した。

## まだ実装していないこと

- `require_member()` の中身（現在は常に通す。雛形のため）
- `members` テーブルと `/api/status`
- 署名付きリンクのトークン検証

これらは連携方式（ステップ2の検証結果）が確定してから実装する。
**関所を1か所に集めてあるので、確定後に書き足すのはその関数だけで済む。**
